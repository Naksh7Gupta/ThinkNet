# Contributing

Ideas, constructive feedback, documentation improvements, and carefully scoped
contributions can help shape ThinkNet.

Before proposing a large change:

1. Open an issue or discussion describing the problem and intended outcome.
2. Explain the proposed approach and any alternatives considered.
3. Keep pull requests focused and include tests or verification steps where practical.
4. Document limitations, assumptions, and any new configuration requirements.

Avoid presenting unimplemented capabilities as completed or introducing
dependencies without a clear reason.

## Quality bar

- Solve a clear user problem and make behavior understandable before execution.
- Surface failures and limitations.
- Test changes on a supported environment.
- Consider resource usage and security implications.
- Keep modules and interfaces maintainable.
